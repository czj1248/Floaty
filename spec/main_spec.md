# 浮启 Floaty 需求规格说明书

## 1. 项目概述

- **定位**：一个轻量的 Windows 桌面悬浮窗启动器。
- **目标用户**：常用程序、文档、文件夹较多，被桌面快捷方式和开始菜单困扰的 Windows 用户。
- **解决的核心问题**：桌面快捷方式一多就乱，任务栏又放不下几个。浮启提供一个始终在手边、又不占地方的启动入口——需要时点开，不需要时缩成一个小球，安静待在角落。

本 spec 覆盖初版（V1）需求，V1 以"悬浮球 + 快捷启动"最小闭环为准。

## 2. 术语定义

- **悬浮球**：应用收缩态的小尺寸悬浮窗口，常驻桌面，是应用的唯一入口。
- **展开面板**：点击悬浮球后出现的窗口，列出全部快捷项。
- **快捷项**：展开面板中的一条启动入口，指向一个启动目标。
- **启动目标**：快捷项指向的具体对象，包括程序、脚本、文档、文件夹、网址五类，支持格式的完整清单见 F4。
- **文件类目标**：程序、脚本、文档三类文件目标的统称，打开行为统一为 Windows 系统默认方式。
- **配置文件**：保存快捷项列表与悬浮球位置的本地 JSON 文件。

## 3. 技术选型

| 项目 | 选型 | 理由 |
|------|------|------|
| 开发语言 | C++17 | 用户指定 C++ 架构 |
| 应用框架 | Qt 6（Widgets 模块） | 无边框、置顶、不抢焦点等原生窗口控制能力成熟；Widgets 足够覆盖本项目 UI，不引入 QML |
| 构建系统 | CMake（3.16 以上） | 用户指定，Qt 6 官方推荐 |
| 编译工具链 | MSVC | Windows 桌面平台标准工具链 |
| 配置存储 | JSON 文件（QJsonDocument 读写） | 满足"不写注册表垃圾"的定位，免安装场景友好 |
| 配置路径 | `%APPDATA%\Floaty\config.json` | Windows 用户级配置的常规位置，卸载不留残留 |

## 4. V1 功能需求（重点）

### F1 悬浮球常驻

- **需求描述**：应用启动后在桌面显示悬浮球。悬浮球为无边框小窗口，始终置顶显示，但不抢夺键盘焦点；按住鼠标左键可将悬浮球拖动到屏幕任意位置；应用重启后悬浮球回到上次位置。
- **验收标准**：
  - 当应用启动，则桌面出现悬浮球，且悬浮球显示在其他应用窗口之上。
  - 当用户在其他应用窗口中打字，则键盘焦点不被悬浮球夺取，输入不受影响。
  - 当按住悬浮球拖动，则悬浮球跟随鼠标移动；松开鼠标后悬浮球停留在当前位置。
  - 当退出应用后重新启动，则悬浮球出现在上一次停留的位置。
- **边界说明**：V1 不做贴边吸附；不做鼠标点击穿透；仅保证主显示器上的正常表现，多显示器精细适配延后。

### F2 展开 / 收起

- **需求描述**：单击悬浮球展开面板，面板列出全部快捷项；点击面板外任意区域或再次单击悬浮球，面板收起为悬浮球。快捷项较多时面板内可滚动。
- **验收标准**：
  - 当单击悬浮球，则显示展开面板，面板中完整列出全部快捷项。
  - 当点击展开面板以外的屏幕区域，则面板收起为悬浮球。
  - 当面板处于展开状态时再次单击悬浮球，则面板收起。
  - 当快捷项数量超出面板可容纳范围，则面板内部出现滚动，悬浮球尺寸不变。
- **边界说明**：V1 不做展开/收起动画，直接显示与隐藏；展开方向在 V1 固定（靠悬浮球上方展开，靠近屏幕上缘时改为向下），不可配置。

### F3 快捷项启动

- **需求描述**：双击展开面板中的快捷项，即启动其对应目标，不支持单击启动，以防误触。文件类目标（程序、脚本、文档）统一以 Windows 系统默认方式打开，等效于在资源管理器中双击该文件：程序文件启动程序，脚本文件执行脚本，文档由系统默认关联程序打开。文件夹用资源管理器打开，网址用默认浏览器打开。启动后面板自动收起。
- **验收标准**：
  - 当双击程序类快捷项（.exe、.lnk），则该程序被启动。
  - 当双击脚本类快捷项（.bat、.cmd），则该脚本被执行，行为与在资源管理器中双击该文件一致。
  - 当双击文档类快捷项，则系统默认关联程序打开该文档。
  - 当双击文件夹快捷项，则资源管理器打开该文件夹。
  - 当双击网址快捷项，则默认浏览器打开该网址。
  - 当单击快捷项，则不启动目标，面板保持展开。
  - 当任一快捷项双击启动成功，则展开面板自动收起为悬浮球。
  - 当启动目标不存在（文件被移动或删除），则界面给出明确提示，应用不崩溃不退出。
- **边界说明**：所有类型统一双击启动；文件类打开行为不做特殊化处理，一律沿用系统默认方式；V1 不支持为程序附加启动参数；不支持以管理员身份启动。

### F4 快捷项管理

- **需求描述**：管理窗口通过悬浮球右键菜单"管理快捷项"打开，窗口内列出全部快捷项，支持添加、编辑、删除。添加文件类目标与文件夹时通过文件对话框选择，添加网址时手动输入；类型按扩展名自动识别；名称可修改；系统自动读取目标对象的图标作为快捷项图标。
- **支持的目标类型全集**（白名单，V1 仅支持以下类型）：
  - 程序：.exe、.lnk
  - 脚本：.bat、.cmd
  - 文档：.txt、.md、.pdf、.doc、.docx、.xls、.xlsx、.ppt、.pptx、.jpg、.jpeg、.png、.gif、.bmp、.webp、.mp3、.wav、.flac、.mp4、.mkv、.avi、.mov、.zip、.rar、.7z
  - 文件夹：任意本地文件夹
  - 网址：http:// 或 https:// 开头的 URL
- **验收标准**：
  - 当点击悬浮球右键菜单中的"管理快捷项"，则打开管理窗口，窗口中列出全部快捷项。
  - 当添加白名单内任一类型的快捷项并保存，则展开面板与管理窗口中出现该快捷项，图标、名称与目标一致。
  - 当选择的文件不属于支持类型全集（如 .reg、.msi、.ps1、.vbs、.js、.scr），则添加被拒绝，并明确提示"不支持的文件类型"。
  - 当编辑快捷项的名称或目标并保存，则展开面板与管理窗口中的显示和启动行为同步更新。
  - 当删除快捷项，则该快捷项从展开面板与管理窗口中消失。
  - 当添加的目标是本地文件或文件夹，则默认图标来自系统读取的目标图标。
- **边界说明**：V1 不支持自定义图片作为图标；不支持拖拽文件到面板快速添加；不支持快捷项排序（按添加顺序显示）。

### F5 配置持久化

- **需求描述**：快捷项列表与悬浮球位置保存在本地 JSON 配置文件中，应用启动时读取。不写注册表。
- **验收标准**：
  - 当增删改快捷项或拖动悬浮球后退出应用，则配置文件中记录了最新状态。
  - 当应用启动时配置文件存在，则快捷项列表与悬浮球位置恢复为上次状态。
  - 当应用首次启动（配置文件不存在），则以空快捷项列表和屏幕默认位置启动，并创建配置文件。
- **边界说明**：不做云同步；不支持多套配置。

### F6 右键菜单与退出

- **需求描述**：悬浮球支持鼠标右键菜单，菜单包含"管理快捷项"与"退出"两项："管理快捷项"打开管理窗口（见 F4），"退出"保证常驻应用有明确的退出途径。
- **验收标准**：
  - 当右键点击悬浮球，则弹出右键菜单，菜单中包含"管理快捷项"与"退出"两项，且不触发展开面板。
  - 当点击右键菜单中的"管理快捷项"，则打开管理窗口。
  - 当用户点击右键菜单中的"退出"，则应用完全退出：进程结束，悬浮球消失。
- **边界说明**：V1 右键菜单仅含"管理快捷项"与"退出"两项，不提供设置等其他入口；关闭展开面板（点击外部）不等于退出应用。

## 5. 非功能需求

- **内存占用**：稳态运行（悬浮球收起、无交互）时进程内存占用不超过 50MB。
- **启动速度**：冷启动到悬浮球可见不超过 1 秒（普通机械硬盘环境除外）。
- **单实例**：同一时刻只允许一个 Floaty 进程运行；当应用已在运行时再次启动，则不创建第二个实例。
- **安装形态**：提供绿色免安装的程序目录（可执行文件 + 运行库），不写注册表，删除目录即完成卸载。
- **系统要求**：Windows 10 及以上版本。

## 6. V2 及以后

以下功能明确延后，不进入 V1：

- 分组管理——按类别收纳快捷项（来源：README 核心特性；已确认不进 V1，延后至 V2）
- 自定义外观——自定义图标、悬浮球大小、透明度、展开方向（来源：README 核心特性）
- 贴边吸附——悬浮球靠近屏幕边缘时自动停靠（来源：讨论结论）
- 多显示器精细适配（来源：讨论结论）
- 程序启动参数、以管理员身份启动（来源：讨论结论）
- 拖拽文件到面板快速添加快捷项（来源：讨论结论）

## 7. 待确认问题

当前无待确认问题。V1 范围已经用户确认：分组管理不进 V1；退出途径为悬浮球右键菜单（不使用系统托盘）。
